快速摘要

Voyager 是 2023 年由 NVIDIA / Caltech / UT Austin / Stanford / ASU 聯合提出（Linxi "Jim" Fan 與 Guanzhi Wang 主導），第一個用 LLM 驅動、能在開放世界中終身自我學習的 embodied agent。它在 Minecraft 中跑，靠三件設計就能自己訂目標、自己寫 code、自己累積技能、把學到的技能轉移到全新世界 — 整個過程零人類介入、零 fine-tuning，完全靠對 GPT-4 的 blackbox API 呼叫。三件神器是：(1) Automatic Curriculum 讓 GPT-4 根據當前狀態生成「下一個該探索什麼」的目標；(2) Skill Library 把 GPT-4 寫的可執行 JavaScript 程式碼存起來，用 embedding 索引，新任務時取最相關的 top-5 組合使用；(3) Iterative Prompting 把環境 feedback、執行錯誤、self-verification 灌回 GPT-4 修正程式。實驗結果：3.3x more unique items、15.3x faster wooden milestone、能在新 Minecraft 世界 zero-shot 解新任務。對你來說，這篇是理解你最近狂收的 Hermes Agent、Skill-creator、SkillsBench、Building Skills Guide 為何長那樣的根源論文 — 不讀它就只能讀 derivative。

Part I — 為什麼 Voyager 是分水嶺？

在 Voyager 之前，「LLM agent」基本上就是一次性 prompt 解一題（你給目標，模型給計畫，跑完結束）。問題是 — 它不會記得自己學過什麼，每次都是從零開始。

Voyager 第一次把「終身累積」（lifelong learning）從強化學習領域搬到 LLM agent 上，而且全程不更動模型權重 — 完全靠 prompt engineering + 外部記憶結構。

Voyager is the first LLM-powered embodied lifelong learning agent in Minecraft that continuously explores the world, acquires diverse skills, and makes novel discoveries without human intervention.

關鍵突破點：

  • 無監督：沒有人告訴它要做什麼
  • 無 fine-tuning：純 GPT-4 blackbox API call
  • 真的會累積：今天學的可以明天用，可以後天遷移到新世界
💡 為什麼選 Minecraft

Minecraft 是「開放世界 + 有明確 tech tree（科技樹）」的完美實驗場 — 既有結構化目標可以衡量進度（木 → 石 → 鐵 → 鑽石），又是無界探索空間（地圖無窮、任務無限）。

對比之下，AlphaGo 環境太封閉（19×19），ChatGPT 環境太抽象（沒有 embodiment）。Minecraft 是兩者中間的甜蜜點。

⚠️ 「分水嶺」是什麼意思

Voyager 之後幾乎所有 code-based agent 都長得像它：寫 code → 跑 → 看 error → 改 code → 跑 → ...... + 把寫過的 code 存起來重用。

你 library 裡的 Hermes Agent（自我改進）、Skill-creator epic update（自動評估）、SkillsBench（評測 skill）、甚至 Claude Skills 本身 — 設計哲學的 DNA 都來自這篇。

Part II — 三件神器深入

神器 1：Automatic Curriculum — Agent 自己訂目標

傳統 RL 需要人類設計 reward function，傳統 LLM agent 需要人類給 task。Voyager 的 curriculum 把這件事交給 GPT-4 自己決定。

具體機制：

  1. 把當前環境狀態（agent 位置、背包、附近方塊、生命值等）餵給 GPT-4
  2. Prompt：「根據當前狀態，提出下一個適合的探索目標 — 不要太簡單、不要太難、最大化發現新東西」
  3. GPT-4 回答 e.g. "找到並挖到 3 個鐵礦"
  4. 這個 task 成為下個 iteration 的目標

關鍵設計：curriculum 是 emergent 的，不是預先規劃的。GPT-4 在每個時間點動態生成最適合當下能力的下一步。

📚 對應的人類學習理論

這對應 Vygotsky 的 Zone of Proximal Development（最近發展區）概念 — 最有效的學習目標，是「比你現在會的稍難一點」的事。

Voyager 的 curriculum 就是把這個概念交給 GPT-4 來判斷 — 而 GPT-4 對 Minecraft 的 prior knowledge 夠強，所以它真的能挑出合適難度的下一個目標。

🛠️ 對你 Skill 系統的對應

你現在的 Skill 都是你決定要寫什麼。Voyager 啟發的版本：給 Claude 看你過去半年的對話紀錄，問「我還缺什麼 skill 會明顯提升我的工作效率？」 — 這就是 personal AI OS 的 automatic curriculum 雛型。

神器 2：Skill Library — 把寫過的 code 存起來

這是 Voyager 最被引用的設計。當 GPT-4 寫了一段 Minecraft JavaScript（例如 "砍樹"），這段 code 不會用完即丟 — 它會：

  1. 用一段自然語言描述包裝（"Chop a tree with bare hands"）
  2. 對描述計算 embedding 向量
  3. 把 (描述, embedding, code) 存進 skill library

未來遇到新任務時，Voyager 會：

  1. 對新任務描述算 embedding
  2. 從 library 取top-5 最相似的 skill
  3. 把這 5 個 skill 當 context 灌給 GPT-4
  4. GPT-4 可以直接重用、組合、或在它們的基礎上改寫

這就是 RAG 的雛型 — 但對象是 skill 而非 document。

⚠️ 為什麼 top-5 而非全部

論文沒詳細討論，但邏輯是 context window 有限 + 太多無關 skill 反而會干擾 GPT-4 的決策。top-5 是經驗折衷。

對照你的 GBrain（Garry Tan 個人知識大腦）— Postgres + pgvector 做 hybrid search 取 top-K — 設計同源，只是知識物件不同。

⚖️ 對應 Claude Skills 的關係

Anthropic Claude Skills 本質上是「人類預先寫好的 Voyager skill library」 — Skills 也用自然語言描述觸發、也用檔案存 code-like 內容。

差別在誰來寫：Voyager 是 GPT-4 自己寫並存，Claude Skills 是人類寫並 deploy。Hermes Agent / Skill-creator 則嘗試把這條鴻溝補起來 — 讓 Claude 自己寫 Skills。Voyager 是這個方向的祖師爺。

神器 3：Iterative Prompting — Code → Run → Error → Fix loop

GPT-4 第一次寫的 code 通常跑不過。Voyager 的 iterative prompting 把錯誤訊息當作 feedback signal：

  1. GPT-4 寫 code v1
  2. 在 Minecraft 環境執行
  3. 蒐集三類 feedback：
    • Environment feedback（"你撞到水了"）
    • Execution errors（"未定義函式"）
    • Self-verification（GPT-4 自己看結果有沒有達標）
  4. 三種 feedback 統統灌回 prompt
  5. GPT-4 寫 code v2，重複直到成功或達上限

論文記錄：63 個獨特 item 用了 160 次 prompting iterations，平均每個 skill 約 2.5 次 iteration 就能成功。

📚 為什麼 self-verification 重要

環境 feedback 與執行錯誤都是「外部訊號」 — 程式跑了會自然產生。但 self-verification 是內部驗證：GPT-4 看完結果，自己判斷「這算成功嗎？」

沒有 self-verification 的話，agent 會把「沒有報錯」誤認為「達成目標」 — 但 Minecraft 中可能 code 跑了但什麼也沒採到。Self-verification 是 lifelong learning 不漂移的關鍵。

⚠️ 對 Hermes 的批判視角

你 library 裡的 Hermes Agent（self-improving）就是這個 loop 的延伸 — SQLite 記憶 + 自動 skill 生成。

但 Hermes 的 self-verification 是用 SQLite 紀錄取代 Voyager 的「GPT-4 自查」 — 工程化但失去了「模型對自己工作的批判判斷」這個關鍵成分。讀完 Voyager 回頭看 Hermes 你會發現它缺了 self-critic 那一環。

Part III — 為什麼用 JavaScript 而非低階控制？

傳統 RL agent 在 Minecraft 中的 action space 是低階馬達控制（前進、轉身、揮手、跳）。Voyager 完全不用 — 它的 action space 是 JavaScript 程式碼，透過 Mineflayer library 控制 agent。

The creators opt to use code as the action space instead of low-level motor commands because programs can naturally represent temporally extended and compositional actions.

為什麼這樣選？

  • 時間延展性（temporal extension）：一行 code 可以代表「砍 5 棵樹」 — 對應幾百個馬達動作
  • 組合性（compositionality）：寫好的 function 可以呼叫其他 function — 自然層次化
  • 可解釋性：人類看得懂 JavaScript，看不懂神經網路權重
  • 遷移性：JavaScript 在新世界仍然能跑 — 訓好的權重未必
🛠️ 「Code as action」是 2024-2026 的主流

Voyager 之後，幾乎所有 code-based agent（包括 Anthropic 的 Claude Code）都採用這個哲學 — agent 的「動作」就是寫並執行程式碼，而非選擇預定義動作。

對比 GUI-based agent（Claude Computer Use、Anthropic Operator）：那條路線是低階滑鼠/鍵盤動作。兩條路線各有適用場景，但需要長期累積能力的場景，code-as-action 幾乎一定贏。

Part IV — 數據結果

⚠️ 模型版本注意

原論文用 2023 年的 GPT-4。Ablation 顯示 GPT-3.5 在 code generation 上明顯落後 GPT-4，因此整套架構的關鍵假設是「夠強的 base model 能寫對 code」。

2026 年用 Claude Opus 4.7 或 GPT-5 跑同樣架構，預期會更強 — 但論文沒有更新。重現實驗時請當「下限證據」看。

重點整理 Key Takeaways

1. Lifelong learning 不需要動權重
Voyager 證明了純靠 prompt + 外部記憶結構（skill library）就能做到累積學習。這顛覆了「lifelong learning = 持續訓練模型」的傳統假設。對 personal AI OS 的啟示是巨大的。
2. Skill Library = RAG for Skills
把 code 用自然語言描述包裝、算 embedding、按相似度檢索 top-K — 這就是現在所有 RAG 的設計。Voyager 把 RAG 從文件檢索擴展到「能力檢索」，是 personal AI OS 最該借鑒的設計。
3. Self-verification 是不漂移的關鍵
三類 feedback 中最容易被忽視的是 self-verification — 讓模型自己判斷「我達標了嗎」。沒有這環，agent 會在 long horizon 越跑越偏。Hermes 等後續 self-improving agent 容易漏掉這環。
4. Code as action space 是 agent 的主流路線
Voyager 確立了「LLM agent 的動作就是寫並執行程式碼」這個典範。Claude Code、Cursor、所有 code-based agent 都繼承這個哲學。GUI agent 是另一條路線，但累積性遠不如 code agent。

練習題 Practice Questions

先在心中思考答案，再點開展開查看建議答案。

Q1 概念理解 Voyager 的「skill library」與你已用的 Anthropic Claude Skills 有什麼根本差別？

機制相似處：

  • 都是「自然語言描述 + 可執行內容 + 按需檢索」三件套
  • 都有 progressive disclosure（按需才載入完整內容，省 context）

根本差別在「誰寫」：

  • Claude Skills：人類預先寫好、deploy 給 Claude 用。是「靜態的 library」 — 加新 skill 需要人類動手。
  • Voyager Skill Library：GPT-4 自己根據環境互動寫的、自己存的、自己組合的。是「動態的 library」 — 每跑一輪可能就多幾個 skill。

啟示：把這兩條融合 — 人類設計 skill 框架，Claude 自動填內容並按使用紀錄優化 — 才是 personal AI OS 的終極形態。Hermes Agent / Skill-creator 是朝這個方向的初步嘗試。

Q2 應用設計 如果要把 Voyager 的設計搬到「個人知識管理 / personal AI OS」場景，三件神器分別對應到什麼？

對應映射（Voyager → Personal AI OS）：

  • Automatic Curriculum：讓 Claude 看你的對話紀錄、行事曆、最近專案，主動建議「你下一個該學什麼」「你下一個該做什麼自動化」。例如「你最近一週問了 5 次同樣的問題，建議寫成 skill 自動化」。
  • Skill Library：你目前的 SKILL.md 集合就是這個 — 但缺了 embedding 索引層。下一步是加上「按描述 embedding 檢索 top-K skill」的功能，讓新對話自動載入相關 skill 而不需手動 reference。GBrain 已經在這方向上走了。
  • Iterative Prompting：你目前的工作流缺這個 — Claude 寫了 skill 沒人逼它跑、看 error、改。要建立「skill execution log → 失敗自動 retry → 改寫 skill」的 loop。Inspect AI（前一篇文章）是搭建這個 loop 的工具基底。

三者組合就是 Voyager 對 personal AI OS 的完整貢獻。

Q3 批判思考 Voyager 在 Minecraft 中表現驚人，但這個架構有哪些隱藏假設讓它不容易直接搬到 real-world 任務？

三個隱藏假設：

  • 環境 feedback 廉價且即時。Minecraft 中每個動作的後果立刻可見（撞到水、得到木頭、生命值變化）。Real world 的 feedback 通常延遲（你發出的 email 對方一週後才回）、嘈雜（同事的回應未必反映你做得好不好）、或缺失（很多事根本沒人 review）。沒有快速 feedback，iterative prompting 就失效。
  • Self-verification 容易設計。Minecraft 中「我有沒有挖到鑽石」是布林判斷。Real world 的「這份 deviation report 寫得好不好」是模糊判斷，需要更複雜的 judge。
  • Action 後果可逆。Voyager 砍錯樹沒事，重新生一個。Real world 中很多動作不可逆（送出 email、提交 batch report、做出投資決策）。Voyager 那種「先試再改」哲學在不可逆場景需要強得多的 self-verification + human-in-the-loop。

結論：Voyager 適合「快 feedback、布林驗證、可逆動作」的場景 — code generation、數據分析、創意發想。對於慢 feedback、模糊驗證、不可逆動作的場景，還需要加上人類在環的設計。這也是為什麼 Claude Code 是好應用、但 Claude 寫 SOP 還需要人審的根本原因。

🎯 我的行動結論
✔ 核心洞察
Voyager 是我最近 4–5 月狂收的所有 self-improving agent / skillification 文章（Hermes、Skill-creator、SkillsBench、Building Skills Guide、Lessons from Building Claude Code Skills）的祖師爺論文。讀完它我才看懂這些 derivative 在繼承什麼、革新什麼、漏掉什麼。最大的洞察是：lifelong learning 不需要訓模型，只需要「自動 curriculum + skill library + iterative prompting」三件套。我的 personal AI OS 已經有零碎的 skill library 雛型，但還沒有 automatic curriculum 與 iterative prompting — 這是下一階段該補的拼圖。
📈 立即應用
本週可做：（1）把現有 SKILL.md 集合加一個 skills/index.json，每個 skill 帶 description + embedding（先用 OpenAI text-embedding-3-small），這是 skill library 的第一步；（2）寫一個小 prompt template「Automatic Skill Curriculum」 — 餵 Claude 過去一週對話紀錄 + 現有 skill 清單，要它建議「我下一個該寫什麼 skill」；（3）開始用前一篇文章的 Inspect AI 來搭建 iterative prompting 的閉環測試。三件事各別輕量、組合起來就是 Voyager 哲學的個人版實踐。
⚠ 需要補充
這篇是 2023 經典，缺幾個現代延伸：（1）Voyager 之後的進化 — Eureka（NVIDIA 同團隊用 LLM 寫 reward function）、SwiftSage（雙系統思考的 agent）值得讀作續集；（2）Self-Discover（Top 3 #2 的另一篇）對應的是「Agent 自己組合 reasoning module」，與 Voyager 的「自己組合 skill」是兩種互補的 self-organization；（3）真實世界 lifelong agent 的失敗模式 — Voyager 在 Minecraft 沒漂移，但 production 的 self-improving agent 容易陷入「越改越差」的 reward hacking，這是論文沒處理的問題，需要 evals（Inspect AI）這層保險。三個月後重讀本文時，重點該放在「我的個人系統有沒有實現任一件神器」。
